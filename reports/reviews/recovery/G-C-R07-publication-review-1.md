## Must fix

1. **Check all parent ACLs before reading any object, and again before publication** ([inputs.py:81](D:/wt/r07-pub-review1/backend/src/ai_intel/enrichment/inputs.py:81), [inputs.py:89](D:/wt/r07-pub-review1/backend/src/ai_intel/enrichment/inputs.py:89), [publication.py:127](D:/wt/r07-pub-review1/backend/src/ai_intel/enrichment/publication.py:127)). Priority: P1.
   - **What this is:** A revision belongs to both a document and a registered source. Existing read APIs apply source, document and revision visibility together; event visibility alone does not grant access to every parent.
   - **Problem:** After a real seeded source or document is changed from public to tenant-private, `load_event_enrichment_inputs` still calls `ContentStorage.read_verified` and returns the document bytes. It checks revision visibility, but the selected document columns omit document ACLs, and the source query selects category alone. Publication has the same missing parent check: after source revocation, an empty-candidate `versions=FAILED/model_timeout` request is accepted and committed in public scope. These are three independent red cases; the first two assert that object reads must remain zero. No external model or HTTP data leak was exercised or claimed.
   - **Fix:** Fetch source/document/revision scope fields with unambiguous names. Preflight every input against authenticated visibility and derived event scope before the first object read. Recheck all three parent scopes under publication locks even when every attempt has no candidates. Preserve tenant-matched positive paths; do not silently remove a source from the complete roster.
   - **If we skip it:** The loader may send revoked private bytes to a later model call, and empty/failed attempts can bypass the publication scope boundary. This violates AGENTS §5, plan03 §1, and the CR's ACL-before-object-IO promise.
   - **Reproduce / recheck:** `review_runner.py negative_extended`, cases `test_parent_acl_revocation_is_checked_before_object_io[source|document]` and `test_failed_attempt_cannot_bypass_revoked_source_scope`; see `independent_negatives_extended.log/xml`. Add revision and same-tenant controls and compare committed state after rejection. The repair must keep object-read count zero for every denied parent, including a denied later document in a multi-document roster.

2. **Use one lock order for source revision writes and enrichment publication** ([publication.py:317](D:/wt/r07-pub-review1/backend/src/ai_intel/enrichment/publication.py:317), [publication.py:130](D:/wt/r07-pub-review1/backend/src/ai_intel/enrichment/publication.py:130)). Priority: P1.
   - **What this is:** Source collection and enrichment can run at the same time for the same current public document. The publication scope advisory lock is held until the outer transaction ends.
   - **Problem:** The new publisher takes the scope lock through `find_prior_publication`, then waits for `documents/document_revisions FOR UPDATE`. The real `persist_source_response` already takes `hashtextextended('source:' + source_id, 0)` in `ensure_source_registration` at `source_documents.py:373`, then the document lock at line 480, then asks for the scope lock while publishing its revised event. The publisher does not take that existing source lock first. A two-session PG test, using both real services, reproduced the cycle twice. In both runs the writer completed and the publisher raised `OperationalError`, SQLSTATE `40P01`. The test only controls timing with `after_cursor_execute`; it does not mock PG or either service. This is a database abort, not the documented changed-input rejection.
   - **Fix:** Have the publisher acquire the existing production source advisory locks in deterministic source-ID order before taking the scope lock, with a consistent parent/document/revision row-lock order. The direct source persistence entrypoint already uses those locks; changing it merely to add the same lock is unnecessary. Do not add a lock used only by tests, and do not retry only the inner savepoint after a deadlock aborts the transaction. Revalidate the complete snapshot after a concurrent writer wins.
   - **If we skip it:** Normal overlap between collection and enrichment causes failed jobs and unnecessary retries. The concurrent duplicate-request green test does not cover this writer/publisher cycle.
   - **Reproduce / recheck:** `test_source_revision_and_publication_share_non_deadlocking_lock_order`; both outcome JSON files and full red logs are retained. The old synchronization expects the broken publisher to obtain its scope lock first. For a changed lock order, use independent lock observation/new timing instrumentation; do not classify an old barrier timeout as a product failure. Require no `40P01`/lock timeout, correct current-input rejection or fresh success, and no partial publication side effects.
