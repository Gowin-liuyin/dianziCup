## Must fix

1. **A bound unknown generation can be reported as closed when its parent remains** (`candidate/core/windows_actor.py:293-315`)
   - **What this is:** The new reader explicitly returns an enumerated row with `created=None` on OpenProcess, birth, or image lookup failure (`:35-46`). The approved shutdown contract requires unknown birth for a bound actor or known descendant to refuse, even when the old held process handle has exit ACK.
   - **Problem:** Let the first tree bind actor PID 11. If the remaining tree contains `{11: {parent: 7, created: None}, 7: {parent: 0, created: known}, 0: {parent: 0, created: None}}`, the actor row is not an orphan at `:293`, is excluded by `pid != self.pid` at `:302`, and is skipped by `pid == self.pid` at `:314`. No Job query is required and the method returns success. A previously bound descendant PID 22 also passes if its unknown remaining row has parent 999, with 999 present in the remaining tree but absent from `generations`: `:293/:304` are false and `:314` skips it. The existing bound-PID test only gives the unknown row an absent parent (`test_native_snapshot_offline.py:259-265`), so it misses both branches.
   - **Fix:** Move the existing bound-unknown check to the beginning of each remaining-row iteration, before the orphan condition and before any `continue`. Refuse `created is None` when the PID is in `generations` or its integer parent is in `generations`. Keep the complete-Job exclusion only for unrelated unknown orphan rows. Add direct cases for a bound actor with its parent present and a bound descendant with a present unrelated parent; both must raise `OwnershipError` and never publish a positive descendant receipt.
   - **If we skip it:** `stop_controller.py:85/90` accepts the return and writes `owned_descendants_exited=True` at `:101`. With matching producer ACKs and old held exit ACKs, `controlled_supervise.py:56-66/:586-589` can request the observer's final read. No exception occurs, so the whole-Job fail-closed catch is never reached. The held old identity does not prove that an unknown remaining row is unrelated. This contradicts the explicit bound-unknown refusal contract; this note does not claim an actual native occurrence or signal to a foreign process.

## Should fix

2. **Unknown bound generations use the wrong exception category** (`candidate/core/windows_actor.py:230`, also `:209`, `:256`, and `:318`)
   - **What this is:** The native snapshot can return `created=None` for a live process whose read-only image or birth query fails. These identity-bearing paths still call `_snapshot_ticks(str(value))`.
   - **Problem:** For a bound actor, descendant, or parent with unknown birth, this produces `ValueError` from parsing `"None"`. The 05:54:41 authorization says unknown birth for a bound actor or known descendant must raise `OwnershipError`. The new offline test at `test_native_snapshot_offline.py:175-179` deliberately expects `ValueError`, so it verifies refusal but does not verify that approved exception contract. This is a contract mismatch, not a confirmed signal bypass: every real caller catches `Exception` and fails closed.
   - **Fix:** Have the identity-bearing path explicitly raise `OwnershipError` when its required birth is unknown, and assert that type in the direct test. Keep the foreign-orphan exception and all signal decisions unchanged. Root must record this narrow diff before an author changes the frozen class, because the initial authorization otherwise preserves its judgments.
   - **If we skip it:** Current callers still refuse, but recorded failures identify a parser error instead of uncertain ownership and the literal approved exception contract remains unmet.
