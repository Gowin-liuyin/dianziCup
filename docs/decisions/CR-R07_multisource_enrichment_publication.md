# CR-R07 · 九维候选发布与多来源证据合并

状态：awaiting_review；本批只完成共享服务行为，worker/API提交与真实模型接线尚未验收。
本变更落实已批准R07九维、证据引用、冲突保留与持久化目标，不改变评分、盲测或原T卡范围。

## 原问题与行为

ClaimSubmission原只声明一个revision，复合来源的候选证据不能逐来源校验或完整返回。
新增有界additional_sources（最多19个），仅schema3可用；每个source/revision必须真实配对、
符合认证ACL与派生scope，并至少有自己的证据。证据不能落在未声明来源中。
旧schema1/2不接受该扩展。空additional_sources不进入序列化/指纹，旧请求幂等含义保持。
没有新增事实数据库；PG既有claim_assertions/claim_evidence/publication_receipts为权威。

输入服务只载入事件的当前可见PG修订，先ACL再对象IO，限制20修订、每件2MiB、合计8MiB，
逐件核对象hash/size与保存块坐标。CVE只取PG标识且需已注册NVD/厂商原文明确字段支持。
部分解析/截断保留不完整，不转换成全库not_found。

发布时再次核事件版本、current修订、来源/URI/完整性/版本/观测时间/实际块与CVE；
载入文档必须与当前事件的完整修订集合一一相等；遗漏来源、空文档或重复修订拒绝，
不能因本次维度失败而绕过来源完整性检查。
public结构字段重新计算后逐值匹配才能发布supported，模型候选保持unverified/pending。
引用全局坐标由真实block.start_offset转换，支持/上下文语义分开。
请求与所有候选的PG幂等回执同事务提交；重复请求返回原历史标识，不新增事实。
改变输入不能复用旧身份；新请求遇版本变化拒绝。合法failed维度与成功维度同次保存。
非法或越权候选整次拒绝，防止用局部成功掩盖边界破坏。

## 兼容性、迁移与回滚

公开EventDetail schema2未改字段，原单来源引用路径兼容，多来源引用仅来自已声明且可见修订。
无DB迁移，历史原文/claim不覆盖。关闭新富化job或撤回未上线调用方可回滚接线，
已有多来源证据不能用旧单来源投影删除；历史回执与旧请求序列化保留。
公共schema3类型/JSONB原合同不削减；更改后由新独立review核旧调用方与实际API读投影。
