## 通用执行合同

每卡开始读取 AGENTS、执行地图、原任务卡、引用合同、状态与最新交接，核对 Git diff 和资源。先明确输入输出与回归案例，再改代码；生产数据与测试数据隔离。每卡报告保存于 `reports/tasks/Rxx.md`，原始日志保存于 `reports/runs/<run_id>/`，同时回填其覆盖的原 T 卡证据链接。

新增测试使用 `backend/tests/<层>/test_rxx_*.py` 与 `frontend/e2e/` 等实际必要路径，不创建空测试凑数量。涉及后端按卡运行针对性 pytest、Ruff、format、mypy，再跑相关回归；前端运行 lint、typecheck、test、build 和对应浏览器流程。R01 补齐 `python scripts/dev.py check --scope contract|integration|security|frontend|e2e|all`，未实现项返回非零并明确原因。

所有真实数据库测试使用独立项目名、独立端口/数据库、专用 DSN 和显式 test 标识；禁止沿用硬编码默认 DSN 执行清库、downgrade 或 `compose down`。每卡结束记录 `implementation` 与各层 `verification`，代码完成最多 awaiting_review，独立评审后才能 accepted。前置仅在同阶段且所需自动检查真实通过时允许 awaiting_review。
