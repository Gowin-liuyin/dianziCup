## 目标

让推荐产物在**来源事实变化后被重判**：change_events 触发 → 受影响 recommendation 进入重判 → 新版本入历史且旧版本不可变可溯，对应评分项：推荐历史与变化重判（T37/T39、R15/R16 后续）、"更新必须覆盖旧命中/新增命中/原来的空结果"与"原文修订不覆盖历史"两条不变量的产品化。

## 分批步骤（每批一个可提交单元）

- **B1 推荐重判发现器**（纯增量）：新增 `backend/src/ai_intel/revalidation/recommendation_candidates.py`——以 change_events 为源，反查受影响 recommendation（经 recommendation 引用的 evidence/revision 集合），产出候选（复用 `candidates.py` 的 cursor 模式）。直属 unit + integration 测试。验收：新文件测试全绿；`test_r16_assessment_candidates_pg.py` 无回归。
- **B2 重判执行与历史版本化**（触历史合同——见风险1）：新 job 类型经 `runtime_policy.py` 入队 → 重判生成新 recommendation 版本（复用 `prepare_generation`/`commit_generation`）→ `recommendation_mutation_receipts` 记 rejudged 操作（**0029 收据表的 operation 枚举扩展需迁移**——见风险2）。验收：新 integration 文件（历史旧版本不可变、新版本 current、收据可溯）全绿。
- **B3 HTTP 面与"已重判"可见性**（触公共合同——见风险3）：recommendation DTO 增加重判状态字段/游标语义扩展。验收：`test_r15_http_recommendations_pg.py` 无回归 + 新增 HTTP integration 全绿。
- **B4 评测与文档收口**：runbook + R21 骨架扩展一条推荐重判记录类型（0 gold 下仍 `not_computable_no_gold`）。

## 明确不做

- 不改 R15 订阅/生成/历史既有语义与不可变触发器（28 integration + 73 unit/contract 测试为回归门）。
- 不做实时推送（重判是拉取式入队，非 WebSocket/SSE）。
- 不动 assessment 域的 R16 既有 job 语义（`REVALIDATION_CHANGE_JOB_TYPE` 只新增兄弟类型，不改原类型行为）。

## 风险与合同触点

1. **B2 触历史合同**：`r15_recommendations` 不可变围栏意味着重判必须**新行新版本**而非 UPDATE——版本选择语义（current 指针）需 CR。
2. **B2 触迁移**：`0029` 收据 operation 枚举扩展 = 新迁移 `0032_*`，迁移 head 冻结期望（batch21 已对齐到 0031，`tests/` 内 iterate 列表与 range 断言）必须同步走 CR（批次21 的迁移 head CR 先例）。
3. **B3 触公共推荐合同**：`recommendation_contracts.py` 的 DTO 字段被 contract 测试冻结——字段新增需 CR。
4. 重判不得把"来源撤回/变化"误判为可静默降级——missing/mixed 模式沿用 fail-closed（`revision_mode.py` 合同）。
